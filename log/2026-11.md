## 2026-11-22｜meta 仓库自身纳入工程控制策略

**触发**：owner 发现 meta 仓库自己没适配——PR 功能关着、rebase 合并开着、没有登记进 `github-policy.json`，而校验脚本从不检查它。

**判断**
- 不公开 meta 仓库：README 项目清单登记了私有仓库名和用途，公开等于公开私有仓库地图。改为维持私有，按 F2 记「不可用」。
- 两份名单（README 表 / `github-policy.json`）必须合一：README 成为唯一登记处，json 只写期望值，两边对不上直接失败。
- 发现「精简」档与「全量」行为完全相同，是个空标签 → 直接删掉该值，脚本改为只接受 `全量` / `不套用`。

**结果**
- GitHub 设置：PR / Issue 开启、仅 squash、合并后删分支；ruleset、分支保护、tag 保护在免费私有仓库返回 403，记 `rulesetsUnavailable` 并做反向断言（一旦可读就报「记录已过期」）。
- 脚本：`check-github-policy` 改读 README 登记，新增 PR / Issue / 可见性断言；`check-project-contract` 校验档位取值、遍历跳过 `.DS_Store`。
- 共享层三次同步到 5 个项目。
- 收尾：`check-github-policy` OK (6)，`check-project-contract` OK (5)，六仓库只剩 `main`。

**未完成 / 遗留**
